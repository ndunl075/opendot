# Milestone M3 review

Reviewer: Opus (Claude), the other vendor for the GPT-written UI (ARCHITECTURE.md section 13.1, task 3.7), reading `ui/` on branch `m3/ui` plus the daemon and desktop code it talks to (`api/server.py`, `api/web.py`, `desktop/src-tauri`). The review was read-only. Fixes went to the owner of each part: Astra and Terra (UI, through the Codex CLI), and Opus (daemon and desktop). The reviewer then re-checked every fix.

The first verdict was "not ready until U1, U2, U3, U4, U7". After the fixes, round 2 confirmed U1 to U14 and found U15. Round 3 confirmed U15. Final verdict: **ready**.
Every finding is fixed or accepted with a reason.

## UI review (task 3.7)

| # | Severity | Finding | Disposition |
|---|---|---|---|
| U1 | High | A new chat adopted the conversation id of the first stream event from *any* conversation (the daemon fans every event out to every subscriber). A rerun of conversation A, or a second window, made the new chat show A's reply and send into A. | **Fixed** (Astra). A new conversation starts with REST `chat_send`, which returns its id. The stream drops every event until that id is bound, then every event for another conversation. Tests: `chat-conversation.test.tsx`, `stream-reconnect.test.ts`. |
| U2 | Medium | Reopening a conversation replayed every old event. An already-decided approval came back with live Approve/Deny buttons, and an old budget or top-tier pause came back with a live "Continue anyway". | **Fixed** (Opus and Astra). `ChatHub.replay` makes replayed events current: approval cards carry the approval's status now, and pauses whose task is no longer paused are dropped (test `test_replay_never_brings_back_a_decided_approval_or_a_stale_pause`). The UI takes the approval's status from `approval_get`, and shows pause actions only after a fresh confirmation. Tests: `chat-conversation.test.tsx`, `pause-verification.test.tsx`. |
| U3 | Medium | Every error showed "Something went wrong". A bad or rotated token made chat retry forever, and 409/410 told the user to retry actions that can never succeed. | **Fixed** (Astra). A session error links to `/login` (web) or says "Restart OpenDot" (desktop). 404/409/410/422 show the server's message, refresh the item and hide dead actions. Socket retries stop after 5 attempts with backoff. Tests: `review-feedback.test.tsx`, `stream-reconnect.test.ts`, `chat-screen.test.tsx`. *Residual Low, accepted:* the daemon refuses a bad token before accepting the socket, so browsers see close code 1006, not 1008. Chat then says the connection could not be restored instead of "session expired". The footer health check still reports "unauthorized" and links to sign-in, so the user has a way out. |
| U4 | Medium | The "Always allow this" dialog only said it creates a rule. The daemon's always-allow also approves and runs the pending action now. | **Fixed** (Astra). The dialog reads "Approve this action now and allow it automatically next time" and names the action and target, and the button reads "Approve and create rule". Test: `chat-screen.test.tsx`. |
| U5 | Medium | The desktop init script wrote the token into `window.__OPENDOT__` on every top-level navigation, whatever the origin. There was no navigation guard and no system-browser path for external links (Google refuses OAuth in embedded webviews). | **Fixed** (Opus). The init script writes only on the app's own origins. `on_navigation` keeps the main window on the app's pages, and `on_new_window` denies popups. External http(s) links without credentials open in the system browser through `tauri-plugin-opener`. |
| U6 | Medium | Reloading Settings or Usage swapped the whole screen for a skeleton, losing unsaved edits, success notices and focus. | **Fixed** (Astra). Resources keep their data while refreshing, and screens stay mounted. Tests: `settings-screen.test.tsx`, `usage-screen.test.tsx`. |
| U7 | Medium | With ChatGPT credit use on, onboarding still let the user confirm "I kept credit use off" (section 6.1 point 10). | **Fixed** (Astra). While credits are on, the acknowledgement is disabled, and "Check again" re-reads the status. Test: `onboarding-screen.test.tsx`. |
| U8 | Low | On a plan-limit pause, "Manage usage" was a secondary link (section 6.1 asks for it as the action). | **Fixed** (Astra). "Manage usage" is now primary and resume is secondary. Test: `paused-banner.test.tsx`. |
| U9 | Low | After a reconnect with nothing to resume, the composer could stay disabled forever. | **Fixed** (Astra). A reconnect, a failure or 30 s without activity clears busy and offers a manual retry. Nothing is resent automatically. Test: `chat-conversation.test.tsx`. |
| U10 | Low | Screen readers announced every streamed fragment. | **Fixed** (Astra). The streaming message is `aria-busy`, and only the final text is announced, in a separate polite region. Test: `chat-conversation.test.tsx`. |
| U11 | Low | "Manage usage" rendered as a link without an href when the URL was rejected. | **Fixed** (Astra). The link renders only for a valid URL; otherwise the screen shows explanatory text. Test: `usage-screen.test.tsx`. |
| U12 | Low | Activity's rule links reloaded the whole app, and Rules never scrolled to the linked rule. | **Fixed** (Astra). Router links, plus a shared scroll-and-focus-on-hash hook for Rules and Memory. Test: `review-navigation.spec.ts`. |
| U13 | Low | Approve was one click even when the reviewer's verdict was "block". | **Fixed** (Astra). A blocked verdict asks for confirmation, quoting the reviewer's note. Test: `chat-screen.test.tsx`. |
| U14 | Low | The footer health check ran once and treated 401 as "unavailable". | **Fixed** (Astra). It re-checks every 30 s and on window focus, and tells "unauthorized" apart from "unreachable". Test: `health-status.test.tsx`. |
| U15 | Medium | (Round 2, introduced by the U2 and U3 fixes) An approval in status `edited` had no actions left, so an edited action could never be decided. | **Fixed** (Terra). `edited` is actionable like `pending`, and a test covers saving an edit and then deciding. *Cosmetic Low, accepted:* an edited approval shows a neutral "edited" badge rather than "Needs your approval". The daemon does not implement editing until M4 (it returns 501), so this cannot happen yet. M4 revisits the wording. |

## Found while building M3 (fixed or accepted by Opus)

| # | Finding | Disposition |
|---|---|---|
| B1 | Astra hit contract gaps while building the screens: no "continue anyway" or top-tier approval endpoint, no way to resume after the plan limit, no task id on paused events, and the reviewer note existed only inside the streamed preview. Section 8.3 requires a "continue anyway" button; section 7.1 requires the top tier to ask first. | **Fixed.** Added `POST /v1/tasks/{task_id}/continue`, `POST /v1/tasks/{task_id}/approve-top-tier` and `POST /v1/companion/resume-plan-limit`, `task_id` on paused events, and `review_note` and `review_verdict` on `ApprovalItem` (durable, from the loop's step record). Tests: `tests/api/test_server_real_loop.py`. |
| B2 | Remaining contract gaps reported by Astra: no model-catalog endpoint, no memory lookup by id or pagination, rule create/update lacks the tool, target, sensitivity and cost fields, and no local-provider address field. | **Accepted for M4.** The UI uses what the contract offers and invents nothing. These endpoints need the connectors, memory and provider settings work of M4. |
| B3 | The PyInstaller sidecar missed sqlite-vec's native extension, so the frozen daemon crashed on its first database connection. The build's own smoke test only ran `--help`. | **Fixed.** `--collect-all sqlite_vec`. The build's smoke test now runs `init` against a temporary database (migrations and extensions). |
| B4 | On this machine, `cmd.exe` cannot see pnpm (or uv), so package scripts that called `pnpm` or `uv` by name failed. Terra and Astra hit this too. | **Fixed.** Package scripts and Playwright web servers never call pnpm, npm or corepack by name. Desktop scripts use `npm_execpath` and Node, and `uv` is found by path search (`desktop/scripts/run.mjs`, `ui/scripts/mock-server.mjs`). |
| B5 | The daemon's mock server did not select the `opendot` WebSocket subprotocol, so browsers rejected the handshake. Astra had added a UI-side adapter. | **Fixed.** The mock selects the subprotocol like the daemon does (test `test_mock_chat_socket_selects_the_opendot_subprotocol`), and the adapter is gone. |
| B6 | The daemon could start before the first ChatGPT sign-in with an empty model catalog, so routing would fail forever. | **Fixed.** `Router.refresh`. The loop re-reads the provider's catalog once when no model fits. Test: `test_empty_catalog_at_startup_is_reread_on_the_first_request`. |
| B7 | If the desktop app is force-killed (rather than quit from the tray), the daemon sidecar it started keeps running. | **Accepted.** The next launch attaches to it: health returns 401 from the same daemon, and the shell reuses it. M4's `opendot service` makes the daemon a long-lived service anyway. Tray Quit stops a daemon the app started. |
| B8 | The installer is unsigned. | **Accepted until release.** Signing certificates cost money and need the user's accounts: listed under Needs you (section 11). Unsigned builds are fine until a public release. |
| B9 | Contract-type generator bug: indentation split on a literal `\n` string. | **Fixed** (Terra). |
