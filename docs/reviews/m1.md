# Milestone M1 review

Reviewer: Sol (`gpt-6-sol`, effort high, read-only) via `codex exec`, over `git diff -M m0/restructure..HEAD` (M1 work on top of M0).
Every finding is fixed or accepted with a reason.

| # | Severity | Finding | Disposition |
|---|---|---|---|
| F1 | High | `opendot measure` called `build_registry()` without its required arguments, so a normal run failed before reaching the plan. | **Fixed.** The default path builds `ChatGPTPlanProvider` directly; other providers need `--provider-factory`. Test: `test_the_default_real_run_builds_the_plan_provider_directly`. |
| F2 | High | The spend cap reserved input cost only, so one call could overshoot by its whole answer. | **Fixed.** `SpendTracker.check` also reserves a bounded output estimate (`OUTPUT_RESERVE_TOKENS`, 512) before any request. Tests: a cap smaller than the reservation refuses with no request sent; the existing trip test now uses a cap with room for one call. |
| F3 | High | Plan requests have no daily budget check, so if the user allowed ChatGPT credits and the plan limit returned billable responses instead of a 429, requests could continue. | **Accepted for M1.** The usage meter and daily hard stop are task 2.5 and scenario S5 of M2, enforced in the router before every plan request. M1's provider exposes the raw usage and `credit_spend_detected` for that, and `opendot measure` checks for credit spending. Onboarding (M3) tells the user to keep credits off. Carried into M2's review checklist. |
| F4 | Medium | `ProviderRegistry.stream` checks enablement but not the feature switch. | **Accepted.** A provider is usable only when enabled, keyed and capped; feature switches gate which product features may *ask* for a paid provider, and are enforced where those features are called (M2 router, reviewer, memory search). Enforcing a feature name at the registry call boundary needs those callers to exist. Carried into M2. |
| F5 | Medium | In-stream error messages bypassed the key scrub. | **Fixed.** `_http.py` scrubs errors raised from inside the stream. Test: `test_a_key_echoed_in_an_in_stream_error_is_scrubbed`. |
| F6 | Medium | No startup catalog discovery for an existing session. | **Fixed.** `ChatGPTPlanProvider.load_models_on_start()` (quiet when signed out); tests for both cases. The daemon calls it at startup in M2. |
| F7 | Medium | The real plan provider has no `stream_websocket`, so the WebSocket measurement is always UNKNOWN on a live run. | **Accepted.** HTTP with full history is the flow's documented default path (section 6.1 point 6); a WebSocket path is not needed for v0.1. The measurement is reported honestly as UNKNOWN with the reason, which is what section 8.5 asks for when a path is unavailable. Revisit if the live run shows a meaningful cost difference. |
| F8 | Medium | The contract had no models or endpoints for feature switches, spend caps or saving keys. | **Fixed.** Seven endpoints added under `/v1/providers` (enable, save/remove API key, feature switches, spend, spend cap); responses can never carry a key (test); mock server and `contract/` regenerated. |
| F9 | Medium | The pause check ran at iterator creation, not at send time. | **Fixed.** `_stream` re-checks the persisted pause immediately before the request. Test: `test_an_iterator_created_before_a_usage_limit_does_not_send_after_the_pause`. |
